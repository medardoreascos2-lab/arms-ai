## Session authority

`SessionStateAuthorityV1` projects the existing certified calendar and special
hours snapshots. All instants must be aware; UTC instants are converted to
America/Chicago. Ambiguous/nonexistent special-hours wall boundaries return
UNKNOWN. There is no automatic holiday source or assumed date coverage.

| State | Meaning |
| --- | --- |
| UNKNOWN | Missing coverage, invalid time or uncertain calendar boundary |
| PRE_OPEN | Before an explicitly certified special-hours opening |
| REOPENING | Scheduled open interval without an admitted closed minute from that interval |
| OPEN | Scheduled open interval with a canonical closed minute from that interval; freshness remains a separate check |
| DAILY_MAINTENANCE | Existing Monday–Thursday 16:00–17:00 Chicago break |
| WEEKEND_CLOSED | Existing Friday 16:00 through Sunday 17:00 Chicago closure |
| HOLIDAY_CLOSED | Explicit certified closed date |
| EARLY_CLOSE | After an explicit special-hours close earlier than 16:00 |
| SCHEDULED_CLOSED | Other explicitly covered closed interval |

PRE_OPEN is not a fabricated premarket period. REOPENING is a readiness state,
not a claim that the exchange has not opened. Provider connectivity is never
deduced from any of these states. OPEN alone does not mean data/risk/account ready.

`CurrentCandleAuthorityV1.reasons()` now includes session vetoes. Current PAPER
strategy analysis requires a ready data gate; account exits still process an
eligible final candle. A close at the scheduled boundary may resolve an existing
local position without allowing strategy analysis or a new entry. There are no
synthetic exits while prices are absent. Freshness checks also reject old forming
bar labels wrapped in a fresh transport timestamp and raw/forming events emitted
during closed hours. Exact retransmissions remain non-executing duplicates.

| Session / provider | Validate market data | Analyze | New local entries | Position handling |
| --- | --- | --- | --- | --- |
| OPEN / CONNECTED | Yes, existing validation required | Only fresh canonical data | Also requires enable, risk, recovery and all existing gates | Existing canonical eligible closes |
| OPEN / DISCONNECTED | No | No | No | Preserve state, no guessed fill |
| Closed / CONNECTED | No new open-session data; heartbeat is separate | No | No | No synthetic mark/exit |
| Closed / DISCONNECTED | No | No | No | Preserve state; review continuity |
| REOPENING / CONNECTED | Fresh event validation only | Wait for canonical close | No until all gates pass | Existing validated close path |
| REOPENING / CONNECTING | No | No | No | Preserve state |
| UNKNOWN / CONNECTED | No | No | No | Fail closed |
| HOLIDAY_CLOSED / CONNECTED | No | No | No | No synthetic observations |

Every row has external SIM authority DISABLED. The native reader also forces
local entries off. Generic current PAPER remains distinct from the read-only
native smoke composition. Clearing generic data continuity never grants external
order authority or certifies native reconnect behavior.

## Gaps, HTF and offline evidence

Existing candle admission proves every missing minute closed, with explicit date
coverage and a seven-day bound. Missing open minutes latch recovery. Older Friday
or pre-maintenance observations cannot acquire freshness from a connected provider.
The unchanged aggregator emits only complete consecutive UTC-instant buckets;
completed historical context is retained, while `htf_current_session` separately
counts newly completed bars in the current open interval. It is not a new strategy
warmup threshold. No synthetic gap filling or look-ahead is introduced.

Tests exercise maintenance, weekend and both 2026 DST weekends, late/repeated/
out-of-order events, unknown calendars, explicit synthetic holiday windows and
multi-day local PAPER accounting. Positive strategy witnesses are explicitly
synthetic safety tests reused from Sprint 08, not injected production scores or
profitability research. Real detector tests run separately unchanged.

`session_source_evidence_sprint12.json` records privacy-safe facts from the already
installed ETH template: source hash, 2026 holiday/partial-holiday metadata, original
trading-day constraints. These are local template facts, not independent exchange
certification. Its trading-day exceptions must not be blindly mapped to civil
dates. The existing special-hours snapshot allows one interval per civil date;
it cannot express every overnight holiday interruption/reopen. Leave an ambiguous
date uncovered rather than silently opening its unverified hours. Full holiday
native and current-calendar coverage remains pending. Synthetic window tests prove
the gate contract, not that their fixture dates are exchange holidays.

## Future SIM discovery and safety

Offline reflection inspected **type metadata only**, never Account.All, account
instances or property values. Installed Core 8.1.8.2 exposes Account.Provider,
Account.Connection and AccountStatus; Provider has a Simulator enum member.
AccountStatus is Enabled/Disabled/LiquidationOnly/Excluded, not account class.
SimulatorInitialCash/delay properties and a reset event are not proof of simulation.
No explicit public IsSimulation/AccountType classification property was found.

The official [Account class](https://docs.ninjatrader.com/ninjascript/account_class)
documents account access and uses a name-selection example; that example is not
strong SIM attestation. NinjaTrader documents a mixed
[live/simulation environment](https://ninjatrader.com/support/helpGuides/nt8/live_simulation_environment.htm).
Global simulation mode, display name, provider connection and market entitlement
must not independently grant ARMS account eligibility.

Provider.Simulator is a candidate for a future pinned, version-audited local
simulator classification, subject to vendor-confirmed account binding semantics.
External provider demo/funded/real classification requires provider-authoritative
evidence; no name heuristic is implemented. Until that contract is established,
actual eligibility is UNKNOWN_ACCOUNT_INELIGIBLE. The pure classifier accepts
explicit authoritative evidence only as an offline design input; no native adapter
exists that can supply or activate it in this sprint.

`FutureSimGatesV1` tests PAPER_RESEARCH, proven SIMULATION, explicit allowlist,
OPEN, CONNECTED, fresh data, exact contract, risk ready, recovery clear, emergency
clear, native market certification and explicit SIM authorization. Every missing,
malformed or failed gate vetoes the contract. Even all passing inputs return
external_order_authority=false: this is a future contract, not permission to send.

`OfflineOrderJournalV1` is a single-caller SQLite idempotency model with stable
opaque-namespace decision digests. It has no account handle, executable order,
quantity/price, dispatcher, network or PnL writer. Identical decision/submission/
ack/fill/cancel messages do not repeat state changes. Contradictions, restart with
pending state and ambiguous reconnect latch durable RECOVERY_REQUIRED. Partial
fills/amendments and authoritative reconciliation remain future adapter work;
unknown terminal evidence is quarantined, never guessed or resent.

## Bounded future native harnesses

`python -m backend.market_data.native_certification_v1 --help` describes the CLI.
Use the installed Python launcher (`py`) on this workstation. The harness waits
for exactly one new market UUID file and then pins it; it never merges sessions,
replays old captures using a substituted clock, or starts NinjaTrader. The current
reader validates live arrival against the real UTC clock with its existing
heartbeat deadline. Source JSONL stays private and unchanged.

Before activation, prepare a **reviewed private spec**, not a committed dataset:

```json
{
  "provider_enum": "Provider31",
  "expiry": "2026-12-01",
  "contract": {
    "provider": "NINJATRADER:Provider31", "contract": "NQ DEC26",
    "source_timezone": "UTC", "bar_label": "CLOSE",
    "trading_hours_template": "CME US Index Futures ETH",
    "valid_from": "<REVIEWED_UTC_INSTANT>", "valid_until": "<REVIEWED_UTC_INSTANT>"
  },
  "calendar_evidence_file": "<PRIVATE_REVIEWED_EVIDENCE>",
  "calendar_evidence_sha256": "<VERIFIED_SHA256>",
  "covered_dates": [], "closed_dates": [], "special_hours": []
}
```

Empty coverage deliberately admits no market data. Populate dates/windows only
from reviewed evidence. Special hours entries use `date`, `open`, `close`.
Expiry is the native instrument month-label metadata observed in Sprint 11T;
it is not inferred to be the final trading date. A source hash proves unchanged
bytes, not the correctness of a manually prepared calendar mapping. Keep the
spec under private review. Retain all existing risk/freshness configuration.

Start one bounded command **before** opening the saved workspace/adding a fresh
exporter. Use a new state/report path each time. Paths below are repository-relative:

```powershell
py -m backend.market_data.native_certification_v1 --spec .arms-dev/sprint12/native-spec.json --directory .arms-dev/ninjatrader-current --state .arms-dev/sprint12/open.sqlite --output .arms-dev/sprint12/open.json --purpose market_open --seconds 7500
```

For a real daily boundary, launch before the last eligible pre-close minute with
`--purpose daily_boundary`, new paths and up to `--seconds 10800`. Capture through
maintenance and enough post-reopen minutes for a complete hour. The activation
window is bounded (default 180 seconds). No account/order configuration is needed.
Do not run either native command as part of offline tests.

The machine report retains ordered native event timestamps, forming/closed counts,
calendar/provider state transitions, pre-close last candle and HTF counts,
closed-session heartbeat count, first post-reopen observations, source prefix hash,
startup sidecar verification, canonical count, strategy observation, account/journal
checks and zero external calls. The protocol emits no raw tick records, so first
raw tick is explicitly NOT_EXPORTED_BY_PROTOCOL, not fabricated as proven.
Stale rejection is tested offline, never by injecting data into native evidence.

Missing required observations remain PENDING_NATIVE_CERTIFICATION. Invalid
transport, contradictory startup evidence, account drift or execution evidence
fails closed. A bounded observation PASS is not a full session/holiday/reconnect
certificate or an order grant. A delayed pre-close native bar emitted at reopen
must fail the existing freshness check; native certification must establish actual
boundary behavior before any exporter change is considered.
